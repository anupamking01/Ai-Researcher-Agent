# Replaying the complete eight-shard offline CI evidence set

Each shard already publishes a source-bound log, receipt, and selected test-module inventory. Validating one downloaded shard does not establish that all eight shards belong to the same workflow run or that their union covers every test module. This standalone offline verifier closes that *whole-run replay* gap without rerunning pytest or any scientific treatments.

Download the eight `vera-offline-tests-shard-N-<run-id>-<attempt>` GitHub Actions artifacts for a single successful run. Extract each artifact into a real directory named `shard-N` under a common evidence directory, for N=0...7. Each directory must contain exactly `vera-offline-tests.log`, `vera-offline-test-receipt.json`, and `vera-offline-test-modules.txt`. Do not combine artifacts across workflow runs or attempts.

On a clean checkout of the exact tested SHA, run the command below with independently obtained identifiers (from the GitHub Actions run page/API, never from any downloaded receipt):

    python -m scripts.verify_full_ci_shard_set --evidence-root /trusted-download/eight-shards --checkout-sha <tested-40-hex-sha> --run-id <run-id> --run-attempt <attempt> --event push

For PR runs, the tested SHA may be a synthetic merge commit rather than the PR head; use `--event pull_request` in that case. The verifier checks every tracked checkout byte, replays each of the eight logs and receipts against the same supplied SHA/run/attempt/event and pinned dependency files, verifies each saved module list against the deterministic source-tree shard selection, rejects missing/extra shard directories and files, and requires the aggregate union to cover every discovered module once. Directory inventories are now scanned with fixed entry limits: at most eight shard directories and three files within each shard, rejecting the first surplus entry without materializing an arbitrarily large listing. This only bounds enumeration of downloaded evidence; it does not authenticate the artifact source. It outputs per-shard digests and an aggregate count of recorded pytest outcomes. Synthetic regressions check a complete set and missing, duplicated, mixed-run, changed, or symlinked evidence.

**Limitations:** This is a local byte-consistency check of retained evidence, not independent attestation of GitHub runner honesty, egress isolation, actual execution of every test function, artifact uploader, or the original treatment/trace custody. The original five-task pilot remains diagnostic; the automated designated-primary analysis is post-collection and order/evaluator-qualified; retrospective sensitivity analyses are exploratory. Real blinded human scoring and historical report/trace authentication remain pending. No treatments, frozen outcomes, evaluator calls, or human ratings are generated by this verifier.
